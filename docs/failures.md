# 실패·미구현 기능

## 캔버스 (도전 단계)  — 2026-11-11
- 상태: **구현 안 함 (시간 부족)**
- 시도한 것: REA(6.8.0) 정적 분석과 `analysis/` 사본의 문자열 검색. 자세한 내용은 [analysis-log.md](analysis-log.md)의 [캔버스] 항목에 있다.
  - `.canvas` 확장자 등록, 엣지 필드(`fromNode`/`toNode`/`fromSide`/`toSide`), 노드 타입(`text`/`file`/`link`/`group`)까지 확인했다.
  - REA의 `trace_application_feature`는 `"canvas"` 같은 문자열 seed로는 `app.js` 안의 노드를 찾지 못했다.
- 원인 추정:
  1. 일정. 기본 단계와 심화 단계(탐색기, 편집·읽기, 검색, 전환, 팔레트, 탭·분할, 설정, 링크·백링크, Live Preview)를 먼저 하기로 했고, 도전 단계 중에서는 그래프 뷰를 우선했다.
  2. 분석 비용. `app.js`는 압축된 단일 번들(3.3 MB)이다. REA가 모듈 경계를 복원하지 못했고 semantic 노드 한도(파일당 20,000개)에도 걸렸다. 그래서 캔버스의 파일 스키마(최상위 키, 좌표·크기·색상 필드)와 상호작용 규칙을 정적 분석만으로 확정하기 어렵다.
  3. 구현 범위. 무한 캔버스(팬·줌), 노드 편집, 엣지 연결, 파일 임베드를 합치면 단일 기능으로는 가장 크다.
- 다시 시도한다면: 테스트 볼트에서 원본 앱으로 `.canvas`를 하나 만들고, 그 파일(우리가 만든 데이터)을 열어 스키마를 관찰한다. 1차 범위는 텍스트 노드와 엣지만으로 잡는다.
